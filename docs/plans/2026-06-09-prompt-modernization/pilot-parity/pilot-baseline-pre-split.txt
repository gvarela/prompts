## 2. Complete Field List of the Worker Prompt

The worker prompt built by `buildWorkerPrompt(task, taskDetails, contextPackage)` contains:

**Task identity**
- `task.id` — beads task ID
- `task.title` — task title
- `taskDetails.description` — full task description from `bd show`

**Context package — patterns** (from research.md)
- `patterns.testingFramework`
- `patterns.testFileLocation`
- `patterns.fileStructure`
- `patterns.namingConventions`
- `patterns.importPatterns`
- `patterns.errorHandling`

**Context package — design** (from design.md, scoped to this phase)
- `design.phaseGoal`
- `design.successCriteria`
- `design.constraints`
- `design.architecturalApproach`

**Context package — beads**
- `beads.epicId`
- `beads.phaseMilestoneId`
- `beads.mode` (`$BEADS_MODE`)
- Beads commands the worker must use: `bd update [id] --claim`, `bd close [id] --reason "..."`

**Context package — test commands**
- `testCommands.unit`
- `testCommands.specific`
- `testCommands.coverage`

**Context package — file references**
- `relevantFiles[]` — `path:line — description` entries filtered to this task

**Process instructions (TDD cycle, verbatim sections)**
- Step 1: Claim the task (`bd update ${task.id} --claim`)
- Step 2: RED phase — write failing test first, confirm it fails for the right reason
- Step 3: GREEN phase — minimal implementation only, run tests + regression check
- Step 4: REFACTOR phase — clean up while tests stay green
- Step 5: Close the task (`bd close ${task.id} --reason ...`)

**Constraints block**
- ZERO SCOPE CREEP / NO ADDITIONS / FOLLOW PATTERNS / TEST FIRST / ONE TASK ONLY

**Expected output contract**
1. What was implemented
2. Files created/modified
3. Tests added/modified
4. Test commands to verify
5. Issues encountered
6. Task beads status (should be closed)
- Error path: document blockers, leave task `in_progress`, return detailed error information

## 3. Verification Gate Sequence Per Worker (with retry policy)

For each completed worker, in order:

1. **Beads closure check**: `bd show ${taskId}` — status must be `closed`.
   - If `in_progress` (worker crashed/incomplete): verification agent is **not** run. Surface to user with options: (a) retry worker with same context, (b) retry with additional context, (c) mark blocked and investigate, (d) manual intervention. Wait for user direction.
2. **Collect worker output**: files changed, tests modified, test command, summary.
3. **Spawn `wb:task-verifier` agent** with: Task ID, Task Description, Test Command, Files Changed, Tests Modified, Worker Summary. Agent runs tests, checks scope adherence, returns structured markdown report.
4. **Parse verdict autonomously**: look for `### Status: PASS` or `### Status: FAIL` in the report.
5. **On PASS**: add to success log, aggregate modified files/test commands, proceed to next task.
6. **On FAIL — retry policy (max 2 automatic retries)**:
   - **Retry 1**: spawn fix worker (general-purpose agent, **opus** model) with Task ID, original task description, verification report, and instruction to fix the identified issues and close the beads issue. Then re-verify with `wb:task-verifier` using the same context.
   - **Retry 2** (if still FAIL): repeat the fix-worker + re-verify cycle with additional context.
   - **After 2 failed retries**: add to blocking-issues list for the phase checkpoint review and continue to the next task — individual task failure does not block the autonomous loop; it surfaces at the phase boundary.

## 4. Phase Completion Report — Section Headings

The Phase 2 completion report (`✅ Phase 2 Complete (Coordinated Execution)`) contains these sections:

1. **Execution Statistics** — worker agents spawned, total tasks completed, execution mode (sequential)
2. **Beads tracking** — phase milestone closed (ID), unblocked next milestone and initial tasks
3. **Progress Summary** — tasks completed this phase, next-phase task availability (`bd ready`), files modified (code/test counts)
4. **Context Efficiency** — main agent context constant, worker contexts ephemeral, no compaction needed

Preceded at the checkpoint by the manual-verification request message with sections:

1. **Automated checks passed** — tests, linting, build (with commands)
2. **Worker agents completed** — per-worker title + summary list
3. **Beads state** — all phase tasks closed (IDs), milestone ready to close
4. **Manual verification required** — checklist extracted from design.md, ending with the request to reply when complete
